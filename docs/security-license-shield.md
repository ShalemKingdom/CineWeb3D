# Step 10 — Security & License Shield

Status: sandbox, not stable. Scope: three committed npm graphs, actual installed package notices, SBOM and CI hardening. Core browser runtime uses MIT/Apache-2.0 declarations. Root lock contains the development-only path @lhci/cli → lighthouse → @sentry/node → @sentry/bundler-plugins → sentry@0.50.0 (FSL-1.1-Apache-2.0). This is source-available with competing-use restrictions, not currently permissive. Exact sandbox exception only; stable policy blocks it. Do not bundle or redistribute this tooling. Investigate a supported audit alternative or dependency update, with tests; do not force an unverified override or delete Lighthouse functionality.

MPL-2.0 axe-core/Lightning CSS and LGPL native Sharp components are confined to testing/build/asset tools under the current architecture. Their obligations remain applicable if redistributed; do not ship node_modules or native libraries. Blue Oak, PSF, CC0 and listed permissive terms are allowed by this project policy, subject to notice obligations. Unrecognized terms fail closed. Root runtime cannot use these copyleft tooling exceptions. Astro and asset graph dependencies are classified as build/CLI scope, not proof that none reaches a generated site. Review actual final bundles and the Three.js bundled Draco/Meshopt notices separately.

Commands: npm run security:check (locked graph); npm run security:check -- --installed (collect original top-level license/notice files with SHA-256); npm run security:stable -- --installed (strict, expected to fail while FSL remains). GitHub Actions produces CycloneDX SBOM, npm audit JSON, inventory and original notices. Missing optional platform packages are distinguished from missing required packages. An installed notice collection is evidence, not full legal clearance; nested licenses, noninstalled platform artifacts, external programs, model weights, generated content and source/media rights still require review. No GPU/model downloads. Keep preview noindex. No release or main merge.

CI actions pinned to verified full commit SHAs; audit all severity levels before npm ci; read-only tokens, no persisted checkout credential. Use committed locks rather than silently regenerating them in CI. Remaining: repository-level branch protection (step 14), stable release check, actual binary/asset notices and final distribution review. Sources: https://docs.github.com/en/actions/reference/security/secure-use ; https://fsl.software/ ; https://www.mozilla.org/en-US/MPL/2.0/FAQ/ ; https://blueoakcouncil.org/license-faq .
