# Physical-device diagnostic protocol

This is a procedure, not a performance result. Use only a reviewed noindex preview on a private network. Do not send credentials, personal data or private media to the device. Record commit, build hash, exact device, OS/browser, screen resolution/DPR, power mode, network, temperature and test date; obtain owner consent where applicable.

1. Run `npm ci --ignore-scripts`, the repository security/license checks and `npm run build`. Serve a private preview; the default Vite preview binds to localhost. To reach it from a device, use a controlled private network or USB port forwarding; do not expose it to the public internet.
2. Open the preview with browser remote developer tools (Chrome DevTools USB inspection on Android, Safari Web Inspector on iOS). Disable cache for cold runs. Record transferred and decoded bytes through load and after selecting 3D separately, including actual compression and resource waterfalls. Capture traces with the browser's Performance panel for at least three runs; record LCP, CLS, main-thread tasks, input latency, and active frame durations. Do not infer field INP from a laboratory trace.
3. Compare initial state, 3D activation, repeated scroll and return to static mode. Check screenshots visually at identical viewport and DPR, reverse scroll, reduced motion, data saver and WebGL context loss. Record errors, power/thermal conditions and median plus range; use a fixed interaction script and preserve traces/screenshots locally.
4. Record JavaScript heap from developer tools as a heap measurement, not total memory. Browser graphics counters and canvas pixel count are proxies, not GPU memory or GPU execution time. If the device/browser provides a supported GPU profiler or disjoint timer query, record its method, support, units and disjoint/error status; otherwise mark GPU time/memory **not measured**. Do not report SwiftShader or emulation as physical GPU results.
5. Compare with a baseline built from the same dependencies, content, device and protocol. Report failures and skipped checks. Never use screenshots or estimated FPS as proof of energy or GPU-memory improvements. No telemetry is enabled by this protocol.

For an automated Chromium laboratory sample, serve the Vite preview locally and run `CINE_MEASURE_URL=http://127.0.0.1:4179/ node scripts/measure-browser-1441.mjs`. This uses Chromium DevTools Protocol and reports the Three.js network resource, JavaScript heap snapshot and total main-thread task-time delta around activation. It uses SwiftShader by default, includes work from the whole page, and is not a physical-device benchmark. The script launches a local browser and sends no telemetry itself.
